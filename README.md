# SSHnesh

Локальный настольный SSH-клиент с MCP по stdio. В верхней полосе находятся «Главная», SFTP и открытые терминалы. Боковое меню «Главной» открывает серверы, хранилище ключей и журнал MCP. Кнопка MCP справа показывает разрешения, запросы и историю. Терминал занимает всю рабочую область, когда панель закрыта. Для локальной работы подписка не нужна. Синхронизация между устройствами пока не реализована.

## Windows x64

Распакуйте `dist/SSHnesh-0.4.1-win.zip` в обычную папку и запустите `SSHnesh.exe`. Сборка без подписи. Для самого SSH-клиента Node.js и .NET после распаковки не нужны. Для запуска MCP-адаптера установите Node.js 22.12+ и сделайте его доступным для MCP-клиента. При необходимости укажите полный путь к `node.exe` в поле `command`.

Если раньше вы использовали SSHash, сохранённые серверы, ключи и пароли подхватятся из прежнего каталога профиля. Если вы сменили папку установки, скопируйте настройки MCP заново, чтобы обновить путь к адаптеру.

Для сборки из исходников нужны Node.js 24, npm и .NET SDK 10.

```powershell
npm.cmd ci
npx.cmd install-electron
npm.cmd start
npm.cmd run dist:win
```

Для Linux предусмотрены `npm ci`, `npx install-electron`, `npm start` и `npm run dist:linux` на Linux x64 с зависимостями Electron и AppImage. Перед запуском убедитесь, что процесс наследует `SSH_AUTH_SOCK`. Windows — проверенная платформа MVP.

## Подключение

1. В настройках сервера укажите адрес, порт, пользователя и способ входа. Для пароля выберите «Пароль» и нажмите «Сохранить и ввести пароль…». Поле в системном окне уже выбрано для ввода. Для приватного ключа сначала откройте «Ключи → Импортировать ключ», затем выберите «Ключ из хранилища» в настройках сервера. Для существующей настройки OpenSSH оставьте «Системный SSH-агент».
2. Нажмите на карточку сервера. Каждое подключение открывает отдельную вкладку. Если импортированный ключ защищён парольной фразой, SSHnesh попросит её при первом подключении с этим ключом после запуска.
3. При первом подключении сверьте показанный SHA-256 fingerprint через независимый доверенный канал. Например, администратор может получить fingerprint ED25519 через серверную консоль командой `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`. Для RSA или ECDSA используйте соответствующий публичный файл. При изменении сохранённого fingerprint подтвердите новый только после проверки.
4. Для копирования выделите текст и нажмите Ctrl+C или Ctrl+Shift+C. Без выделения Ctrl+C передаётся терминалу.
5. В SFTP выберите локальную папку слева и подключённый SSH-сеанс справа. Откройте каталоги и перетащите файл в противоположную панель или нажмите стрелку в его строке. Файл копируется в открытый каталог назначения. При совпадении имени существующий файл сохраняется. При обрыве отправки на сервере может остаться часть файла. Для скачивания в локальную папку требуется файловая система с поддержкой жёстких ссылок, например NTFS.

Для рабочего подключения можно создать отдельную пару командой `ssh-keygen -t ed25519 -f "$HOME/.ssh/sshash_work"`. Задайте парольную фразу и самостоятельно добавьте только `sshash_work.pub` в соответствии с правилами вашего сервера. SSHnesh не меняет серверный доступ и не импортирует данные Termius. Для аппаратного ключа предусмотрен путь через совместимый агент с поддерживаемой идентичностью, например PIV с обычным RSA/ECDSA-ключом. Конкретный аппаратный агент и PIN-подтверждение требуют проверки. Типы OpenSSH `ed25519-sk` и `ecdsa-sk` в текущей версии SSH-библиотеки не поддерживаются.

## Подключение MCP

1. Откройте панель MCP и нажмите «Настройка». В буфер скопируется готовый объект `mcpServers` с путём к адаптеру и ключом сопряжения. Добавьте запись `sshash` в конфигурацию вашего MCP-клиента со stdio. Храните ключ как локальный секрет.
2. Включите MCP в приложении. Откройте нужный терминал и нажмите «Передать MCP». При передаче другой сессии приложение попросит подтвердить замену.
3. Клиент вызывает `list_shared_sessions`, чтобы получить `sessionId`, `generation` и `grantId`. Для `request_terminal_input` и `request_terminal_output` он передаёт эти три поля, новый UUID `requestId` и абсолютный `expiresAt` в миллисекундах Unix. Максимальный срок с момента приёма — 90 секунд. Таймаут MCP-клиента должен покрывать выбранный срок.
4. Для проверки запросите `echo hello`. Сверьте адрес, пользователя, сессию, соединение и строку. Нажмите «Отправить в PTY». Затем запросите новый вывод через `request_terminal_output` с `maxChars`, например 1024. Отредактируйте фрагмент и подтвердите передачу.
5. `cancel_request` отменяет ожидающий запрос того же MCP-соединения. Протокольная отмена MCP также поддерживается. Статус «Отправлено в PTY» означает запись в канал. Результат исполнения неизвестен. Отмена после записи не останавливает удалённый процесс. Для прерывания используйте обычное действие в терминале, если оно уместно для запущенного процесса.

`integration_status` показывает состояние интеграции. Скрытие панели, переход между страницами, потеря фокуса и сворачивание окна сохраняют разрешение. При разрыве SSH, переподключении, замене переданной сессии или выключении MCP ожидающие запросы отзываются. Новому SSH-соединению разрешение выдаётся заново.

## Границы доступа и карта исходников

- [src/main.cjs](src/main.cjs) — доверенный процесс Electron. Создаёт изолированное окно, проверяет источник IPC, хранит адресную книгу и fingerprints локально. Ключ сопряжения MCP защищён DPAPI через Electron Safe Storage на Windows. На Linux без системного хранилища используется ключ на время запуска.
- [src/sessions.cjs](src/sessions.cjs) — ssh2, проверка ключа сервера, три способа аутентификации и удалённый PTY. Проверка серверного ключа обязательна. Перенаправление агента выключено.
- [src/credentials.cjs](src/credentials.cjs) и [bridge/SecretDialog.cs](bridge/SecretDialog.cs) — защищённое хранилище и отдельное Windows-окно ввода. На диске пароли и ключи сохраняются зашифрованными через DPAPI текущего пользователя. При подключении секрет загружается в память доверенного процесса. У ключа с парольной фразой сохраняется исходный зашифрованный файл под дополнительным слоем DPAPI. Саму фразу приложение не сохраняет. Интерфейс видит только метаданные ключей и наличие пароля, а экспорт доступен только для публичной части. MCP к хранилищу доступа не имеет.
- [src/access.cjs](src/access.cjs) — единственная выданная сессия, абсолютные сроки, защита от повтора, ожидание решения и отмена. Решение о записи проверяется в том же проходе цикла событий, в котором происходит запись. Новое соединение получает новый UUID.
- [src/mcp.cjs](src/mcp.cjs), [src/local.cjs](src/local.cjs), [bridge/Program.cs](bridge/Program.cs) — MCP SDK, проверка обеих сторон канала с HMAC и одноразовыми значениями, именованный канал Windows с ACL текущего пользователя и запретом сетевого доступа. На Linux используется UNIX-сокет в каталоге с правами 0700. Стандартный ввод и вывод MCP используются для JSON-RPC.
- [src/files.cjs](src/files.cjs) — SFTP в доверенном слое по тому же проверенному SSH-соединению. Локальная панель ограничена деревом папки, выбранной через системный диалог. MCP имеет собственный список из пяти операций и не получает доступ к файлам, ключам или адресной книге.
- [src/ui](src/ui) — интерфейс и xterm.js. Скроллбэк остаётся в интерфейсе. Для MCP в памяти собирается только новый вывод с момента передачи сессии, до 16 384 единиц UTF-16. Один фрагмент ограничен 4096 единицами. Передача требует решения человека. Очистка управляющих символов не распознаёт секреты. Вывод маркируется как недоверенный.

Доступ рассчитан на границу между локальным MCP-клиентом, изолированным интерфейсом и доверенным процессом. Программы с теми же правами пользователя, администратор и скомпрометированный агент находятся вне этой границы. Ключ сопряжения может оказаться в буфере обмена и настройках MCP-клиента. Сохраняйте эти настройки локально и удалите секрет из истории буфера, если она включена. После смены ключа сопряжения нужно обновить конфигурацию клиента. Для сброса закройте SSHnesh и удалите `pairing.dat` из каталога данных приложения.

DPAPI защищает данные на диске от других учётных записей. Процесс с доступом к вашей сессии Windows, отладке, дампу или памяти может получить доступ к расшифрованному секрету. Импорт не меняет исходный файл. Для аппаратной защиты используйте совместимый системный агент с поддерживаемой аппаратной идентичностью. Windows Hello и FIDO2 напрямую не интегрированы.

## Архитектура

Рассматривался Tauri 2. Выбран Electron, поскольку в рабочей среде доступен Node.js, а Electron даёт одинаковый Chromium и модель изоляции на Windows и Linux. SSH и SFTP реализует ssh2, терминал — xterm.js, stdio — MCP SDK. .NET-помощник на Windows нужен для явной ACL именованного канала. Он поставляется со своим рантаймом.

Документация: [Tauri](https://v2.tauri.app/start/prerequisites/), [изоляция Electron](https://www.electronjs.org/docs/latest/tutorial/security/), [Safe Storage](https://www.electronjs.org/docs/latest/api/safe-storage), [ssh2](https://github.com/mscdex/ssh2), [xterm.js](https://xtermjs.org/docs/), [MCP stdio](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), [ACL именованных каналов](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights), [OpenSSH ssh-add](https://man.openbsd.org/ssh-add.1).

## Проверка

`npm test` запускает модульные проверки правил доступа. `npm run test:e2e` после сборки запускает Windows Electron, отдельный OpenSSH-сервер и отдельный OpenSSH-агент в WSL, затем stdio-адаптер из приложения. Для стенда нужен тестовый дистрибутив WSL с непривилегированным пользователем по умолчанию, пакетами `openssh-server`, `openssh-client` и `netcat-openbsd`. По умолчанию используется Ubuntu. Другой дистрибутив задаётся через `SSHASH_TEST_WSL`. Стенд использует временные ключи, каталоги и локальные адреса. Серверы из пользовательского профиля не используются.

Автоматический сценарий покрывает реальный PTY, Unicode, resize, обмен по MCP, отмену, отказ, истечение срока, две вкладки, сворачивание окна, разрыв связи, отзыв доступа, повторное подключение и смену ключа сервера. Для SFTP проверяются обе панели, перетаскивание в обе стороны, побайтовое сравнение, отказ при совпадении имени и запрет выхода за границу выбранной папки. В тесте заменён системный диалог выбора папки. Windows-скриншоты в `test-artifacts` сохраняются при прогоне. Отдельно проверен запуск распакованного ZIP из временного каталога с чистым профилем, создание окна и запуск помощника именованного канала.

Сквозной тест дополнительно проверяет импорт ключа с парольной фразой и вход с сохранённым паролем и ключом после перезапуска. Для импорта ключа тест подставляет выбор файла и фразу. В сценарии пароля тест нажимает кнопку в настройках, проверяет видимое Windows-окно с маскированным полем, вводит тестовый пароль с клавиатуры и подключается к SSH после перезапуска. Отдельно `powershell.exe -NoProfile -File test/secret-dialog.ps1` проверяет отмену. Аргумент `accept` проверяет передачу тестового значения через канал помощника. Снимки окна Windows просмотрены вручную. Физический аппаратный токен и запуск Linux-сборки требуют отдельной проверки.

`powershell.exe -NoProfile -File test/release-password.ps1 -Archive dist/SSHnesh-0.4.1-win.zip` запускает распакованную Windows-сборку с тестовым профилем и проверяет ввод пароля с клавиатуры сразу после активации кнопки в настройках. Тест не подключается к SSH.

## Ограничения MVP

- Один переданный SSH-сеанс, до восьми ожидающих запросов. История содержит последние сто исходов в памяти и не сохраняет текст команд или вывода. При отправке через PTY команда может попасть в уже запущенную программу либо продолжить набранную строку. Перед подтверждением проверьте состояние терминала.
- Один запрос ввода содержит одну строку и Enter. Пакеты команд, удалённый exit code и автоматическое прерывание процессов отсутствуют.
- SFTP работает с открытым SSH-терминалом. Передача идёт по одному обычному файлу. Перетаскивание поддерживается между панелями приложения. Рекурсивные операции, очередь, удаление и переименование файлов в этой версии отсутствуют.
- Windows поддерживает вход по паролю, импортированному ключу и системному агенту. Отдельное окно пароля и парольной фразы пока реализовано только для Windows. Keyboard-interactive, SSH-сертификаты, Jump Host и импорт SSH config не реализованы.
- Нет облачной синхронизации, автоматического обновления, мобильной версии и RDP. Windows ZIP распространяется без подписи.
