# SSHnesh Preview на Tauri 2

Прототип использует существующие экраны SSHnesh и xterm.js. SSH и SFTP работают
через Rust. В пакет не входят Electron, Node.js и .NET. На Windows и Linux
тот же исполняемый файл обслуживает MCP через stdio в режиме `--mcp`.

Поддерживается вход по паролю с проверкой отпечатка ключа сервера,
интерактивный терминал и SFTP в обе стороны для обычных файлов.
При совпадении имени файл назначения не перезаписывается.
На Android локальная панель показывает папку SFTP приложения. Для ввода в
терминал на Android используйте поле строки под выводом; передача отдельных
клавиш и сочетаний пока не поддерживается.

В карточке сервера откройте **Учётки**. Укажите проверенный отпечаток ключа
сервера, пользователя и путь к приватному ключу для каждой нужной роли.
Роли `debug` и `admin` используют разных пользователей. SSHnesh сохраняет
настроенный профиль, отпечаток и пути к ключам, но не копирует секреты и
не передаёт их MCP-клиенту. Поддерживаются существующие ключи без парольной
фразы. Системный SSH-агент пока недоступен. Обычный вход по
паролю по-прежнему работает в пределах запуска.

В меню MCP нажмите **Скопировать команду для Codex**, затем выполните её
в PowerShell (Windows) или терминале (Linux). Команда регистрирует уже
распакованный экземпляр приложения: `codex mcp add sshnesh -- /путь/к/sshnesh-preview --mcp`.
Откройте новый чат и попросите «Покажи серверы из SSHnesh». В приложении
Codex можно также добавить MCP вручную: команда — полный путь к SSHnesh,
единственный аргумент — `--mcp`.
Чтобы дожидаться диалога подтверждения, в настройках Codex для этого MCP
можно установить `tool_timeout_sec = 120`. Открытая вкладка терминала не
нужна. На Android MCP пока недоступен.

MCP включён по умолчанию. В панели **MCP** снимите флажок **«Включать MCP
при запуске»**, чтобы отключить обработку запросов; настройка сохранится
и применяется даже когда окно приложения закрыто.

Если SSHnesh уже открыт, выберите подключённый сервер в терминале или SFTP
и попросите Codex: «Посмотри ошибки на сервере, который сейчас открыт в SSHnesh».
MCP получает имя текущего сервера и открывает отдельное подключение под
`debug`. Доступ к текущему серверу можно выключить в панели MCP. После
закрытия окна явные запросы по имени сохранённого сервера продолжают работать.

`list_servers` показывает профили с настроенной ролью. `service_status`,
`read_logs` и `disk_usage` работают под ролью debug: чтение журнала
зависит от прав этого пользователя. Произвольные команды через MCP не
поддерживаются. Пример: «Посмотри состояние nginx.service и его последние
ошибки на prod».

Для `create_user` и `issue_ssh_key` на управляемом Linux-сервере владелец
один раз устанавливает [sshnesh-provision](sshnesh-provision) как
`/usr/local/sbin/sshnesh-provision`, владелец root:root, режим 0755. Через
`visudo` разрешите выбранной администраторской учётке запускать ровно этот
файл, например: `sshnesh-admin ALL=(root) NOPASSWD: /usr/local/sbin/sshnesh-provision`.
Профиль debug это правило не получает. SSHnesh показывает отдельное
локальное подтверждение для каждого изменения с сервером, пользователем и
отпечатком ключа. Отмена или отсутствие графического сеанса отменяют
изменение. Помощник создаёт обычные Linux-учётки и принимает только
публичные Ed25519-ключи для созданных им пользователей без дополнительных
групп. Приватный ключ создает и хранит сам получатель; ему не нужно отдавать
его в чат.

## Вход на Android

На Android в разделе **Аккаунт** откройте вход через xelopat.ru. После
подтверждения браузер возвращает SSHnesh одноразовый код через
`ru.xelopat.sshnesh.preview://auth/callback`. Если браузер блокирует переход,
на странице есть кнопка **Открыть SSHnesh**. Приложение сверяет состояние
входа и обменивает код на сессию по HTTPS. Сессия хранится в памяти.

После входа нажмите **Скачать серверы и ключи** и введите прежний
мастер-пароль хранилища. Android открывает формат старого SSHnesh,
показывает скачанные ключи и использует их при подключении. На устройстве
остаётся зашифрованная копия, которую можно открыть мастер-паролем без сети.
В Windows, Linux и Android кнопка **Сохранить на сервере** объединяет независимые изменения и отправляет зашифрованное хранилище. Если одна запись изменилась с обеих сторон, выберите локальную или облачную версию либо отмените операцию. В разделе **Ключи** можно создать Ed25519 или импортировать файл приватного ключа. При переходе с Electron сначала отправьте последние локальные изменения из старого приложения, затем скачайте хранилище с тем же мастер-паролем. Отдельно открывайте **Настройки** для размера шрифта, истории
терминала и мигающего курсора.

Для работы на публичном домене сначала обновите
[`sshnesh-login.php`](../server/xelopat/sshnesh-login.php) на xelopat.ru,
затем раздавайте APK. Существующий endpoint выдачи сессий совместим.

## Сборка

Из корня репозитория выполните **npm ci**, затем **node prototype/build.cjs**.
Установите Rust и системные зависимости по [руководству Tauri](https://v2.tauri.app/start/prerequisites/).

Из каталога prototype:

- Windows: **npx @tauri-apps/cli@2 build --bundles nsis**. Для portable
  нужен только `sshnesh-preview.exe` и системный WebView2.
- Linux: **npx @tauri-apps/cli@2 build --bundles deb**. Для проверки в Debian
  можно собрать образ из Dockerfile и запустить linux-build.sh, поместив
  прототип в /source/prototype, а каталог для артефактов в /out.
- Android: **npx @tauri-apps/cli@2 android init**, затем
  **npx @tauri-apps/cli@2 android build --apk --target aarch64**.
  Установите версию Android SDK Platform, заданную в проекте Gradle.
  На Windows, если Tauri не может создать символическую ссылку после успешной
  сборки Rust, скопируйте `libsshnesh_preview.so` из `aarch64-linux-android/release`
  в `prototype/gen/android/app/src/main/jniLibs/arm64-v8a/`. Затем из
  `prototype/gen/android` запустите `gradlew.bat :app:assembleArm64Release -x :app:rustBuildArm64Release`.
  Для установки release APK подпишите его своим ключом через `apksigner`.

## Проверка SSH и SFTP

test-sshd.sh запускает тестовый OpenSSH в контейнере. Публикуйте его порт
только на localhost. Передайте порт в SSHNESH_FIXTURE_PORT, отпечаток из
журнала контейнера в SSHNESH_FIXTURE_FINGERPRINT и запустите
**cargo test --release --locked --lib ssh_and_sftp -- --ignored --nocapture**.
Тест проверяет интерактивный PTY, загрузку, список, отказ при перезаписи
и побайтовое сравнение скачанного файла.

Для полного теста MCP используйте `test-native-mcp.py` в одноразовом
Debian-контейнере с OpenSSH, Python, sudo, Xvfb и xdotool. Тест запускает
сборку с `--mcp`, проверяет отказ, подтверждение и вход созданного
пользователя по добавленному ключу. Он меняет только учётки в контейнере.
