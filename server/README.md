# Развёртывание синхронизации SSHnesh

## sshnesh.xelopat.ru

1. Настройте DNS и HTTPS. Укажите `server/public` как корень сайта и включите PHP с расширением PDO SQLite. PHP должен получать заголовок `Authorization`.
2. Укажите в переменной окружения `SSHNESH_SYNC_DB` абсолютный путь к SQLite-файлу в каталоге вне корня сайта. Дайте пользователю PHP право записи в этот каталог. Таблицы создаются при первом запросе.
3. Сгенерируйте 32 случайных байта командой `openssl rand -hex 32` и задайте результат как `SSHNESH_ACCOUNT_SECRET` в окружении PHP на обоих сайтах. Храните его в конфигурации сервера вне общедоступных каталогов.
4. Настройте лимит тела запроса 32 МиБ, `memory_limit` PHP не ниже 256 МиБ и ограничения частоты запросов на веб-сервере. Для резервного копирования используйте средства SQLite.

## xelopat.ru

Поместите `server/xelopat/sshnesh-login.php` рядом с основным `index.php` сайта. На сайте уже есть маршрутизация файлов PHP без расширения. Проверьте, что `/sshnesh-login` открывается и существующие формы входа и регистрации возвращают пользователя на эту страницу. Мост использует `auth/lib.php` сайта, включая существующие сессии, идентификатор аккаунта и CSRF-защиту. База аккаунтов остаётся на xelopat.ru.

После согласия пользователя приложение получает одноразовый подписанный код и меняет его на токен синхронизации. Код действует 90 секунд и привязан к случайному секрету, который генерирует приложение. Токен действует до 12 часов и хранится в памяти приложения.

## Хранилище

PHP хранит зашифрованную копию на аккаунт и номер её ревизии. Запись с устаревшей ревизией получает HTTP 409. При скачивании клиент сравнивает локальную и облачную версии с последней общей зашифрованной копией. Независимые изменения сливаются автоматически. При конфликте правки или удаления в одной записи пользователь выбирает версию. Профиль SSH-сервера и его сохранённый пароль сливаются вместе. Чтобы передать результат на другие устройства, сохраните его на сервере.

SSHnesh выводит ключ из мастер-пароля через scrypt и шифрует копию AES-256-GCM. Подлинность привязана к аккаунту и ревизии. Сервер видит идентификатор аккаунта, ревизию и размер шифротекста. Учётные данные на каждом устройстве защищены его системным хранилищем. При первой локальной записи SSHnesh переносит данные старого профиля в `workspace.json` и дальше работает с ним. Старые локальные файлы сохраняются.

## Локальная проверка

При установленном PHP с PDO SQLite запустите `npm run test:sync`. На Windows можно указать путь к PHP в `PHP_BIN` и каталог расширений в `PHP_EXTENSION_DIR`. Тест поднимает два локальных PHP-сервера с временной базой и проверяет вход с тестовым аккаунтом, передачу шифротекста, получение ключей и паролей, слияние и конфликты.
